# M5 config.ini 格式契约与测试清单

状态：实现前契约草案，2026-09-12；基线 `fa0ca3d`。本文不代表功能已实现或测试已通过。
依据：`Docs/01_PROJECT_OVERVIEW.md` 第三章、`App/inc/app_config.h` 和 `App/src/app_config.c`。文档未定义的语法与长度限制由本契约提出。

## 1. 文件格式

- CLI 入口：`conf`；TF 路径：`/config/config.ini`（FatFs 使用 `0:/config/config.ini`）。
- UTF-8 无 BOM；接受 LF、CRLF 和末行无换行，拒绝孤立 CR、NUL、非法 UTF-8。
- 文件最多 1024 字节，包含注释及换行；单行最多 128 字节，不含 CR/LF，按 UTF-8 字节计数。边界值允许，超出即失败，不截断后继续。
- 每个有效行格式为 `key=value`；键名区分大小写，顺序任意；允许行首、行尾及 `=` 两侧的 ASCII 空格和 Tab。
- 忽略空白行；去掉行首空白后以 `#` 开始的整行为注释，允许中文注释。不支持行尾注释、`;` 注释、节名、引号或转义。
- 以下 8 个键必须各出现一次；缺失、重复（即使值相同）、未知键、空值或多余字符均使整文件失败。

```ini
# 工业数据采集终端配置文件
device_id=0001
sample_period=5
ch0_ratio=1.00
ch0_limit=2.50
ch1_ratio=1.00
ch1_limit=2.50
protocol_mode=0
alarm_mode=2
```

该示例沿用项目总览，属于合法配置示例；当前固件默认 CH1 阈值为 10.50，示例导入后将其改为 2.50。

## 2. 字段规则

- `device_id`：恰好 4 位十六进制，大小写均可，无 `0x` 前缀；范围 `0001`～`FFFE`。`protocol_mode=1` 时仅允许 `0001`～`00F7`（十进制 1～247）。例如 `0010` 表示十进制 16。
- `sample_period`：无符号十进制整数，只允许 5、10、15 秒，遵循项目总览定义。当前 `app_config_validate()` 接受整个 5～15 区间，导入解析层需要额外收紧，暂不修改公共配置校验行为。
- `ch0_ratio`、`ch1_ratio`：十进制实数，闭区间 0～100。
- `ch0_limit`、`ch1_limit`：十进制实数，闭区间 0～500，比较对象为乘变比后的工程量。
- 实数语法：`[0-9]+(\.[0-9]{1,6})?`，最多 6 位小数；允许整数写法和前导零，拒绝正负号、指数、NaN、Inf、`.5`、`1.`、逗号及尾随文字。先检验十进制值域再转 float32，防止越界值因舍入进入范围。
- `protocol_mode`：无符号十进制整数，0=自定义协议，1=Modbus RTU。
- `alarm_mode`：无符号十进制整数，1=主动上报，2=被动存储；允许 `01`/`02` 等前导零。总览示例中的括号解释不属于合法值，应移到单独的 `#` 注释行。
- 十进制整数只接受 `[0-9]+`，前导零仍按十进制解释；转换过程必须检查溢出，不能先窄化再校验。
- 本版文件不增加波特率或版本键；`baudrate`、`rs485_baudrate`、`version` 均按未知键拒绝。候选配置继承请求受理时的运行配置快照中的波特率、采样使能、隐藏模式；保留字节维持 0。8 个文件字段必须完整覆盖，缺失不以快照补齐。
- 持久化版本仍由 `app_config_encode()` 写入 `APP_CONFIG_PERSISTENCE_VERSION=1`，序列化长度保持 31 字节。

## 3. 原子导入及任务边界

`conf → ControlTask/CLI → 请求队列 → StorageTask 完整读文件 → 临时配置解析 → 字段齐全及跨字段校验 → app_config_validate() → 编码 → FlashKV 原子提交与读回确认 → 结果队列 → ControlTask app_config_apply() → 成功反馈`。

- StorageTask 独占 FatFs 与外部 Flash；请求/结果保留 request_id、operation、origin、deadline；快照及结果按值传递，不传可复用接收缓冲区裸指针。
- 任一读取、解析或提交前校验失败，运行配置与原有效 Flash 记录均保持不变。采用先持久化成功、后应用 RAM 的顺序，以本次用户要求覆盖总览中的旧顺序。
- 为避免快照覆盖期间的新修改，建议导入事务期间拒绝其他配置修改及重叠持久化请求；落实时须覆盖 CLI、按键、自定义协议和 Modbus 写入口。实际采集及只读查询继续运行。
- 提交前检查 deadline；提交已开始后不能把超时或结果队列满等同于回滚。必须保留终态并最终对齐 RAM 与已提交记录，成功反馈只能在 RAM 应用完成后发出。
- 提交标志写入后发生读回通信错误时，不能直接断言旧 Flash 仍有效；应重新扫描判定提交结果，在结果确定前报告待确认状态。掉电恢复必须得到完整旧记录或完整新记录，不能出现混合字段。
- 无卡：`TF card not found`；无文件：`config file not found`；语法/字段错误：`config parse error at line N`。N 从 1 开始并计入空行和注释；缺失字段定位到 EOF 后一行。I/O、超时、长度和 Flash 错误分别反馈，不伪装成解析成功。
- 使用静态文件缓冲及候选结构；不引入动态内存或任务栈大数组。FatFs 版本、FF_CODE_PAGE=437 和 LFN 配置保持现状。

- [ ] 完整合法 8 字段、键顺序打乱、整数及实数合法写法、十六进制 ID 大小写；最终字段与输入一致。
- [ ] 空白行、中文整行注释、空格/Tab、LF、CRLF、混合换行、末行无换行。
- [ ] 空文件、仅注释、逐个缺失键、重复键、未知键、大小写错误、空值、缺少/多余 `=`、行尾注释；错误行号准确。
- [ ] 非法整数、溢出、正负号、错误 ID 宽度及 `0x` 前缀；ID 边界 0000/0001/FFFE/FFFF。
- [ ] 周期 5/10/15 接受，4/6/14/16 拒绝；协议 0/1 接受、2 拒绝；告警 1/2/01/02 接受、0/3 及括号说明拒绝。
- [ ] 变比 0/100 和阈值 0/500 接受；负值、刚超上限、超长小数、指数、NaN、Inf、`.5`、`1.` 拒绝。
- [ ] Modbus ID 00F7 接受、00F8 拒绝；交叉字段检验与键顺序无关。
- [ ] 波特率键即使取合法值也按未知键拒绝；服务层注入非法快照波特率须完整校验失败。合法快照波特率及采样使能/隐藏模式成功导入后保留。
- [ ] 128/129 字节行、1024/1025 字节文件边界；BOM、NUL、孤立 CR、非法 UTF-8；总长度包含注释和换行。
- [ ] 中途解析失败、无卡、缺文件、读取中断/短读、提交前超时：RAM 和原有效 Flash 配置保持不变。
- [ ] Flash 擦除/数据写失败：旧记录可恢复；提交标志阶段故障及提交后读回失败：重新扫描确定完整旧/新记录；模拟掉电无混合配置。
- [ ] 请求队列满、结果队列满、过期/不匹配结果、并发配置写入：无覆盖、无重复应用、无错误成功提示；已提交结果最终可交付。
- [ ] 成功导入：完整配置语义一致、编码/解码一致、保存后重新初始化并加载一致；float32 按解析结果比较，不以结构体 padding 比较。
- [ ] AC5 0 Error/0 Warning；记录 ROM/RAM 增量、静态队列/缓冲占用；板上测 StorageTask/ControlTask 栈水位。
- [ ] COM9：config read → conf → protocol/baud 查询 → reset → config read；包含成功文件和失败文件保持旧配置两组。
- [ ] COM14：自定义协议 39/39、Modbus 14/14、heartbeat；记录测试配置并在结束后恢复默认配置。
- [ ] 人工配合：TF 文件准备及物理插拔；软件注入通过不能替代实际拔卡/掉电证据。
